# CONTROLLED BETA TEST PLAN — LINKEDIN AUTOPILOT
**Company:** GT InnoX LLP  
**Product:** LinkedIn Autopilot SaaS  
**Target:** 20 Pilot Users (Founders, Creators, Consultants, Marketing Agencies)  
**Duration:** 14 Days  
**Scope:** Personal Profiles & Verified Organization Company Pages  

---

## 1. Beta Objectives
1. Verify multi-destination LinkedIn publishing reliability across diverse network conditions.
2. Validate the Google Gemini 1.5 Pro AI content generation under varied prompt contexts and user niches.
3. Test time-zone scheduling and dual-engine worker execution (BullMQ Redis primary with Supabase Cron fallback).
4. Measure support ticket responsiveness, error resolution time, and customer onboarding friction.

## 3. Test Scenarios & Protocols

### Scenario 1: Authentication & Onboarding
- **Action:** User signs up with email/password, verifies email, creates a workspace, and walks through the 5-step onboarding guide.
- **Verification:** User profile created in `public.profiles`, default workspace created in `public.workspaces`, owner role assigned in `public.workspace_members`.
- **Pass Criteria:** Zero login hydration errors, redirect to `/dashboard` within 1.5 seconds.

### Scenario 2: LinkedIn OAuth 2.0 Connection
- **Action:** User clicks "Connect LinkedIn" in `/accounts`.
- **Verification:** State CSRF verified, tokens exchanged with LinkedIn API, tokens encrypted via AES-256-GCM before DB insertion in `public.social_accounts`.
- **Pass Criteria:** Account card displays user picture, name, URN (`urn:li:person:...`), and green "Active" badge.

### Scenario 3: AI Studio & 7-Day Plan Scheduling
- **Action:** User inputs a prompt (e.g. "ERP in Construction Field"), selects "Daily" cadence, and clicks "Confirm & Schedule All 7".
- **Verification:** 7 distinct posts generated by Gemini 1.5 Pro, saved to `public.posts` with status `scheduled` and sequential dates.
- **Pass Criteria:** No duplicate posts, all hashtags properly formatted, scheduled calendar displays all 7 cards.

### Scenario 4: Autonomous Background Delivery
- **Action:** Scheduled post reaches delivery time `scheduled_at`.
- **Verification:** Worker daemon or Cron endpoint executes `deliverPost()`, exchanges media assets with LinkedIn Restli API, receives `urn:li:share:...`, updates status to `published`.
- **Pass Criteria:** Post appears live on LinkedIn feed with exact text and media within 60 seconds of scheduled time.

### Scenario 5: Support & Feedback Ingestion
- **Action:** User encounters an issue and submits a ticket via the top navigation Help / Support modal.
- **Verification:** Record created in `public.support_tickets`, operational notification sent to workspace members, visible in `/admin`.
- **Pass Criteria:** Immediate acknowledgment toast and ticket tracker updated.

---

## 4. Exit & Promotion Criteria for General Availability (GA)
- **Zero Critical / Severity-1 Defects:** No authentication loops, no token exposure, no database corruption.
- **99.5% Publishing Delivery Success:** Greater than 99% of valid scheduled posts published successfully.
- **Zero Cross-Tenant Leakage:** Supabase RLS audit confirms zero data bleed across distinct `workspace_id`s.
